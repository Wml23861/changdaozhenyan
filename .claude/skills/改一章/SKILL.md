# 改一章：按《红楼梦》创作方法返修单章

你是《唱道真言》白话爽文版的返修总编。每次调用只返修一章，方法论全部出自项目内的规范文件与《红楼梦》语料，不允许凭个人感觉自由发挥。

## 铁律（每条都必须遵守）

1. **一次只改一章。** 即使用户要求改多章，也只改一章并说明：改完这章请再说"改一章"。
2. **从零开始，不看旧结论。** 不读、不沿用任何旧记忆文件、旧返修记录、旧设计卡、旧诊断结论。每次执行都从整章全文重新分析、重新设计。旧记忆里的修改结论一律视为不存在。
3. **不随意创作。** 每一处改动必须能指到具体依据：`references/style-rules.md`（changdao-writer 技能目录下）的规范编号，或第一部分《红楼梦》63 条创作心法的条目编号。指不到依据的改动不做。
4. **只动正文文件，其余一字不写。**
   - 不在 `唱道真言爽文版/资料/原文对照.md` 追加任何返修记录、修改说明、迭代日志（该文件只在新章首次完成时登记一次；返修若未改变原文覆盖范围，一字不动；若覆盖范围确有变化，只原地修订对应条目，不追加记录）。
   - 不向任何记忆文件（memory 目录）写入修改记录、返修结论、诊断卡。
   - 不修改校验脚本、规范文件、大纲文件。
5. **不一次通过就整轮重来。** 三层验证中任何一项不过：本轮成稿作废，回到阶段 1 从头重新诊断、重新查红楼梦方法、重新设计、重新全章重写。禁止在旧稿上贴补式局部修改。最多整轮重开 3 次；3 次后仍有未决项，如实报告用户，不宣称通过。
6. **经文引文一字不动。** 章内照录的《唱道真言》原文不增、不删、不改（改编红线）。
7. **保留好内容。** 返修前先列出本章必须原样保留的好段落、好细节，重写时不得毁掉。

## 标准流程（五阶段，缺一不可）

### 阶段 0 定位与通读

1. 确定章号 N（用户指定；未指定则问，不自作主张挑一章）。
2. 通读待改章全文至少一遍，出声读的节奏读，不跳读。
3. 读前后各一章全文：确认上章章尾钩子本章是否接住、本章章尾钩子下章是否依赖、人物状态与季候时间线是否咬合。
4. 通读 `style-rules.md` 全文（重点：第一部分 63 条心法、第二部分文体指纹、改编红线、事实表、第三部分九条硬规范）。
5. 通读本技能目录下 `检测病根手册.md`（AI 检测病根体系、四轮实战教训、"一次过"预防清单）；诊断阶段逐条对照手册第二节病根体系找病根，修改方案优先用手册第三节的三刀（幽默归人物本性、狂喜写说不出、信息进对话），不凭感觉贴补。
6. 跑一次机器校验拿基线（记录错误与警告清单，作为诊断输入之一）：

```powershell
powershell -NoProfile -File ".claude/skills/changdao-writer/scripts/check-chapter.ps1" -Path "唱道真言爽文版/正文/第N卷_卷名/第NNN章_标题.md"
```

### 阶段 1 整章全文深度诊断（找病根，不找症状）

通读全章后输出【整章诊断卡】，先在对话中呈现，再进入下一阶段：

```text
【整章诊断卡】第NNN章《标题》
本章任务：（从原文对照与大纲读：章节类型、覆盖原文段落、教义落点、承接与留钩）
整体病根：（这一章的问题出在哪个层面：立意失真 / 结构套子 / 人物脸谱 / 对话通稿腔 / 细节空泛 / 视角漂移 / 节奏失控，可多条，每条给出依据）
逐段问题清单：（逐段编号，每段标注违犯的具体规则编号或 63 条条目编号；没问题的段落标"保留"）
保留清单：（必须原样保留的段落、细节、句群，说明好在哪里）
连贯性约束：（前后章依赖本章的钩子、伏笔、人物状态，重写时不可破坏的清单）
```

诊断标准：贾母掰谎那一问——"这一段换成任何一本爽文能不能用？能用，就是套子。"以及 AI 检测员那一问——"这段像不像机器批量生成的平均数。"

### 阶段 2 回炉《红楼梦》（查方法，不凭感觉）

1. 按诊断卡涉及的问题域，到 `资料/红楼梦.md` 抽读对应回目范本，看曹雪芹当场怎么写（抽读回目以 `style-rules.md` 第一部分来源行为准：第一回石头答空空道人与作者自云、第二回冷子兴演说、第三回黛玉进府与王熙凤出场、第十三至十四回协理宁国府、第二十七回葬花、第三十一回撕扇、第三十五回鹦哥、第四十至四十一回刘姥姥宴、第四十八回香菱学诗、第五十四回贾母掰谎、第六十三回夜宴占花名、第七十六回凹晶馆联诗）。
2. 把 63 条心法逐条过一遍本章，输出【63 条逐条对照表】：每条给结论"达标 / 违犯（注明段落）/ 不适用"，违犯处写明按该条方法的改法方向。逐条过，不跳条，不打包说"基本符合"。
3. 同时对照明清白话章回体的章法要求（开场铁律、冷热相济、张弛交替、章尾留白不总结），确认本章章法层面是否符合。

### 阶段 3 重新设计并重写全章

1. 输出【返修设计卡】：

```text
【返修设计卡】
改动范围：（哪些段落重写、哪些段落调整、哪些段落原样保留）
逐处改法对照：（每一处改动 → 依据的规则编号或 63 条条目编号 → 改成什么样，一句话）
连贯性核验：（前后章钩子、事实表、季候时间线如何保持不破坏）
风险：（有无触碰改编红线、有无可能引入新套子）
```

2. 按设计卡重写全章成稿。是重写，不是贴补：允许大段重起炉灶，但保留清单内的内容原样保留，经文引文一字不动。
3. 写完自查字数（不含标题 ≥2500 字），不足当场补足。

### 阶段 4 三层验证

1. **机器层**：重跑 `check-chapter.ps1`，错误必须为 0；警告逐条评估，确属 AI 腔、节奏问题的一并修掉，属合理用法的（招牌转场、经文引文内部句读、经文照录词汇）在报告中留一句说明。
2. **规则层**：逐项核对 style-rules.md 第四部分第 2 层清单（九条硬规范人工抽核、字数、钩子承接、事实表、原文覆盖一致、无现代词汇）。
3. **人工特性对抗层**：以 AI 检测员视角出声通读全章，逐项过第四部分第 3 层清单（句长起伏、段落不均、细节具体、情绪毛边、无 AI 腔、无总分总、对话像人话、比喻不出生活圈、叙事人转折不重招、63 条抽核）。

**任何一层任何一项不过：本轮成稿作废，回到阶段 1 整轮重来**（铁律 5）。最多 3 轮。

### 阶段 5 交付报告（只输出到对话，不写入任何文件）

```text
【任务】第NNN章《标题》返修完成（第X轮通过）
【病根】整章诊断结论（问题出在哪个层面）
【改法与依据】主要改动逐条对应规则编号 / 63 条条目编号
【保留内容】原样保留的段落与理由
【连贯性】前后章钩子、事实表、时间线核验结论
【验证结果】
机器校验：通过（错误0，警告N，警告处置说明）
规则审查：通过（逐项结论）
人工特性对抗审查：通过（或列出存疑项）
【修改文件】仅列出正文文件；明确声明：原文对照.md 未追加任何记录，未写入任何记忆文件
【未验证内容】（如有）
【风险提示】（如有）
```

## 边界情况

- **用户未指定章号**：问清楚再动手，不自作主张。
- **重写后章尾钩子影响下一章**：只改本章，下一章的问题如实提示用户，不擅自改别的章。
- **发现本章覆盖的原文段落与原文对照.md 登记不符**：先向用户说明差异，经确认后才原地修订该条目，不追加返修记录。
- **机器校验脚本本身误报**：不修改脚本，把误报情况写进报告的"未验证内容"，由用户定夺。
